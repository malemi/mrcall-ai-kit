# Local goal controller

## Intent and scope

Run the persistent Python goal controller under the operator's existing account,
including existing PROBLEMI3 sessions. Separate Linux users, root ownership and
privileged namespaces must not be prerequisites. The operator explicitly rejected
mandatory protection against intentional agent tampering. Preserve Python-owned
continuation, executable acceptance, state/restart recovery, generation fences,
operator limits and uncertain-delivery reconciliation.

Make local mode the normal setup. Retain the existing protected deployment as an
explicit optional mode for compatibility, without implying that local peer UIDs
authenticate the human against an agent. Local control is ordinary account authority;
model instructions restrict agent actions. No account creation or migration.

## Acceptance

- Setup/service/client run as the current non-root account without sudo or PID/mount
  namespaces. Existing native sessions remain addressable without restart.
- Actual installed local CLI/service executes failed acceptance, wakes both idle
  roles, retains state across restart and closes only after corrected acceptance.
- Existing explicit protected mode remains usable; local mode retains bounded
  child runtime/output and process-group cleanup without claiming namespace-grade
  containment or protection against same-account tampering.
- Both supervisor skills and operational docs describe default local setup and
  preserve end notices and late-message handling.
- Refresh the installed assets. Resume the previously requested PROBLEMI3 activation
  using its actual current mandate and executable acceptance; never substitute a
  passing fixture for its real acceptance or silently permit paid retries.

## Constraints

Reuse valid existing evidence and avoid paid model experiments. Scope excludes
new features, account migration, changes to privilege policy and release. Preserve
prior dirty work. Only material changes to the approved goal lifecycle require
additional design. Current mandate/acceptance discovery belongs to activation;
missing indispensable intent or authorization remains explicit.
